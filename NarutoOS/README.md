# Naruto OS 开发说明

应用介绍与下载见[仓库首页](../README.md)，新环境准备与运行步骤见[安装与源码运行](docs/INSTALL.md)。下方保留开发过程与专项检查记录。

为 macOS / Apple Silicon 制作的个人火影 Online 启动器。正式界面由 Swift Native Core 承载，游戏页由 Electron 11.5.0 Intel 宿主承载，并经 Rosetta 运行；默认入口为巴西服。旧项目和 360 浏览器均未修改。

## 运行

本地试用版可直接双击桌面试用目录中的 **Naruto OS.app**。自带 Flash，0.1.10 起默认跟随系统网络设置，不需要开发环境。打包、图标与数据说明见 [本地试用包](docs/LOCAL-PACKAGE.md)。

系统 WebKit 登录/选区嵌在启动器原窗口中，选区后原位置进入 Flash 游戏标签。登录 Cookie 由该账号槽位保存，下次点击开始前恢复；关闭待登录标签也会保存已完成的登录。国服沿用现有流程。应用启动时只显示主页。

开发版使用 Native Core。`pnpm dev` 会构建并启动隔离预览，`pnpm start` 启动已构建的 Native Core；也可双击 **启动开发版.command**。这些入口都不会生成或安装 `.app` / DMG。预览资料位于 `.test-artifacts/native-core-preview/`。**启动直连测试.command** 使用另一份 `.test-artifacts/native-core-direct-live/` 资料，只将游戏会话设为直连，不影响正式应用或系统代理。

启动器不修改 macOS 或 Clash 设置。游戏页跟随系统网络代理。工具栏、菜单和 `⌘R` 共用一个刷新入口：巴西服游戏会重新打开官网登录/选服，登录页本身只刷新当前页面；国服仍按普通方式刷新。巴西服恢复页准备好后，旧页会保留，用户确认新游戏可以正常操作后才完成切换；也可以取消并回到旧页。诊断日志只记录状态码和固定失败阶段。

开发环境：Node.js 22+、pnpm 11、macOS Command Line Tools、Rosetta。终端首次准备：

```sh
cd <克隆到本地的 NarutoOS 目录>
npm_config_arch=x64 pnpm install
python3 scripts/prepare-runtime.py --fallback31
pnpm dev
```

如果终端找不到 Node，本机还可使用 Codex 自带运行时：

```sh
export PATH="$HOME/.cache/codex-runtimes/codex-primary-runtime/dependencies/node/bin:$PATH"
```

Electron 必须为 x64，不能使用 ARM 版配合 Intel Flash。`runtime/flash-34/` 为官方 Flash 34.0.0.384 独立副本；`runtime/flash-31/` 为只读复制的已有备用组件。准备脚本不会执行 Flash 安装器，不修改系统插件或 360。设置中切换版本，下次启动生效。

开发过程的 Electron 官方直链连接失败，当前包由 npm 镜像取得，SHA-256 已与 GitHub 官方 Release API 下载的 `SHASUMS256.txt` 核对一致：`32937dca29fc397f0b15dbab720ed3edb88eee24f00f911984b307bf12dc8fd5`。Flash 安装包 SHA-256 为 `824dfe95a40b674acc0ab139bf4c86250a7b19f5cf3c23cd948866ef0ab2fc12`，提取后的插件通过原始代码签名验证。

## 使用

- 设置 → 游戏 →“默认画质”可保存低／中／高三档，默认高；修改后应用已有 Flash 实例，新实例和刷新后沿用。右键菜单可临时调整当前实例。真实游戏战斗效果见开发验收记录。
- 设置 → 游戏 →“游戏汉化”控制巴西服已有汉化内容，默认关闭。修改后可选“稍后重启”或“立即重启”；重启会结束游戏会话并回到主页面，游戏需重新打开。同一个应用内切换，无需安装两个版本。
- 每次启动只显示知言启动页，不恢复上次的游戏标签或网页。右上角切换国服的朱砂执扇版／巴西服的墨绿挥手版；主页用下拉框直接选择当前地区的账号档案，点击“开始游戏”才打开它固定的登录环境。没有档案时可从主页直接新建。地区和所选档案分别记忆，官网继续负责选择具体区号。
- `⌘T` 或顶部加号打开账号选择入口，可切换并打开其他档案；同一档案已经打开时会切回原标签，不会再开一个副本。切换标签或回主页时，登录和恢复会留在后台继续；明确关闭登录标签或取消恢复才会结束流程。巴西服同一时间只运行一个登录/恢复流程，已打开的其他账号仍可切换，未打开的新账号会显示忙碌提示。
- 设置里的“登录档案”区域用于新建、改名、填写／清空常用区服备注和删除不用的档案。删除会清除该档案在本机的 Cookie、网站数据和会话登录快照，不会注销官网账号，也不会删除独立保存的密码；清理中断后可在设置里重试。档案名称只是你给登录环境起的名字，启动器不会读取网页身份来验证；备注只是提醒，官网实际选择的区服由你手动确认。历史槽位会以“历史登录槽位”显示，并提示“登录身份待自行确认”；打开官网核对后可以改成自己的名称。
- 本次运行中有游戏标签时，点顶部房屋图标或按 `⇧⌘H` 返回启动页，后台标签继续运行。重新启动后回到无游戏标签的主页面。
- 直接打开游戏；`⌘T` 新建、`⌘W` 关闭。工具栏和 `⌘R` 使用同一刷新操作：巴西服游戏重新获取游戏入口，国服刷新当前页面，登录/选服页刷新当前页面。恢复的新游戏页就绪后，需确认可正常操作再点“完成切换”；取消则保留原页。
- `⌃Tab` / `⌃⇧Tab` 切换，`⌘1…8` 按序选择，`⌘9` 最后一个标签。
- 双击或右键标签修改备注，备注与账号互不绑定。
- `⇧⌘M` 总静音；仅当前标签有声，后台标签保持运行。
- 默认深浅色跟随系统；设置中可手选主题、自定义标题栏颜色，偏好会保存。
- 启动页按地区展示账号档案胶囊菜单；支持调整背景颜色、跟随主题背景和开关轻动画，偏好会保存。
- `⌘,` 打开设置，可手动新增、查看、编辑和删除已保存密码。记录写入独立钥匙串，保存不验证密码正确性。
- Electron 登录表单和巴西服原生 WK 登录页均支持选择当前网站已保存的账号并填入账号与密码，不会自动提交。
- Electron 登录表单识别到登录提交并离开表单后，顶部提示保存或更新；用户点击保存才写入钥匙串。巴西服提示可保留到区服页面，保存或暂不后恢复游戏视口。跨网站不会移用密码。
- 关闭最后一个标签后保留空白入口；退出有标签的窗口时提醒一次。
- 所有 HTTP/HTTPS 导航、弹出链接和重定向均在当前标签内打开，不调用默认浏览器。此项以用户后续确认覆盖早期方案的外链策略。
- 主页面就绪后结束标签加载指示；后到的 iframe 或社交资源不会重新开启转圈。巴西服密码登录一次只保留一笔请求，提供密码错误、403、429 和超时提示。认证成功但区服加载失败时停止并提示手动刷新，不自动重读登录状态、刷新页面或重新提交密码。

## 数据与模块

开发预览的隔离资料位于 `.test-artifacts/native-core-preview/`；集成检查使用各自的 `.test-artifacts/native-core-*` 目录和合成档案。Native Core 通过原生钥匙串接口管理凭据，测试目录与正式应用数据分开。

国服／巴西服各档案使用固定持久分区。网站存储与有有效期的Cookie由Chromium保存；会话Cookie存入独立钥匙串服务 `cn.youye.naruto-os.sessions`，在首次网页请求前恢复。官网设定的有效期保留，主动退出登录会同步移除状态。关闭标签释放网页及回调，退出程序前等待保存完成。

`src/prototype/native/` 提供 Swift 窗口与 Native Core；`src/prototype/host/` 提供游戏 Electron 宿主。`src/main/` 保留宿主复用的游戏会话、登录、Flash、凭据、配置、导航、汉化与达摩辅助模块；`src/preload/game.ts` 是游戏页最小权限桥接。`src/renderer/` 提供共享启动器界面。远端页面开启 sandbox / contextIsolation、关闭 Node / remote；没有访问整个密码库的接口。

## 验证

```sh
pnpm verify
pnpm test:sessions
pnpm test:web-login
pnpm test:integration
pnpm test:login
pnpm test:network
pnpm test:native
pnpm test:focus
pnpm test:refresh
pnpm test:memory
pnpm test:resource-bridge
```

`pnpm verify`执行类型检查、构建和模块测试，不包含集成或安装包测试。其余命令为按功能选择的专项检查。

`pnpm test:integration` 运行 Native Core 的维护、窗口和操作归属专项检查。`pnpm test:package` 读取 `release/latest-native-package.json` 指向的 Native Core 包；源码修改后需先生成新包，旧包的结果不用于验收新源码。打包与安装按用户授权进行。

模块测试使用内存合成数据。Native Core 集成测试使用 `.test-artifacts/native-core-*` 隔离目录和合成账号，不访问正式账号。

`pnpm test:sessions` 使用独立配置、本机网页及专用合成钥匙串，连续启动三个 Electron 进程，验证双地区 Cookie／localStorage 保留、首次请求已带 Cookie、同地区标签隔离、退出登录及 Cookie 到期后不恢复。测试结束清理专用钥匙串项；不退出正式游戏或使用真实账号。

登录回归使用官网原版 jQuery 1.7.2 与原版登录函数、本机 HTTPS 合成接口和独立会话。仅该测试会话信任临时生成的固定证书；所有请求都留在回环接口，不连接官网或钥匙串。生产超时为 15 秒，测试页面将该定时器缩短以验证失败路径。详见 `docs/LOGIN-DIAGNOSIS.md`。

网络回归在本机分别启动合成目标服务和拒绝代理，验证首笔页面请求绕过代理、HTTP/HTTPS 解析为 DIRECT、新标签继承，以及其他会话代理不变。界面回归包含保存按钮的真实命中/鼠标点击、区服跨域提示保留、保存后的高度恢复，以及官网原版 CSS 下反馈文字的横排与隐藏。

资源与内存测试使用独立配置和空白页面，连续四轮创建并关闭五个标签，检查回调解除、渲染进程退出、保留标签与分区隔离、同分区重开及异常销毁清理。每轮记录应用各进程工作集、主进程内存和 JS 堆，结果保存在独立的 `.test-artifacts/session-memory-*/results.json`。资源清理失败会使测试失败；内存变化作为观测数据写入报告。

深浅色截图和集成结果在 `.test-artifacts/`。用户已在诊断窗口直连登录巴西服并进入游戏；本次修复后的真实登录体验、多账号长期在线和游戏操作仍需使用验收。启动器不更改系统网络或代理设置，直连仅影响自己的登录和游戏会话。

开发验证可通过 `NARUTO_TEST_PROBE=qq` 在独立 `NARUTO_DATA_DIR` 打开用户提供的国服入口，默认产品入口不变；该模式不启用 QQ 密码保存。
